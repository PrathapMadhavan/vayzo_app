1. Document Purpose
This Software Requirements Specification defines the functional, non-functional, technical, operational and business requirements for VAYZO Phase 1. VAYZO is a local on-demand platform that allows customers to order food, ask partners to purchase and deliver items, and book local bike or car rides.


2. Product Vision
VAYZO is not intended to be only a traditional food-delivery application. Its core differentiator is a request-based service model:
You Ask. We Get It.
Customers can type or speak what they need. VAYZO converts the request into an actionable service request that can be assigned to a suitable partner.

10. Recommended Core Request Architecture
A common requests table should be used rather than creating completely separate order systems for every service. The request_type field can distinguish:


FOOD


BUY_GET


BIKE_RIDE


CAR_RIDE
This architecture will simplify partner assignment, tracking, notifications, reporting and future expansion.

13. Non-Functional Requirements


Normal API responses should target under approximately 2 seconds under expected load.


All list APIs must support pagination.


HTTPS must be enforced in production.


Role-based authorization must be implemented.


All user input must be validated server-side.


File uploads must validate type, size and access permissions.


Payment data must be handled through the payment gateway; sensitive card data must not be stored by VAYZO.


Rate limiting and abuse protection should be enabled for authentication and public APIs.


System architecture should support expansion from Melur to multiple towns without redesigning the core request model.


Audit logs should be maintained for critical admin and financial actions.

18. Phase 1 Acceptance Criteria


Customer can register/login and reach the dashboard.


Customer can submit a text request and a voice-to-text request.


Customer can create a Buy &amp; Get request with multiple pickup locations.


Eligible partner can receive, accept and complete a request.


Partner can upload purchase bills for Buy &amp; Get requests.


Customer can track active requests.


Customer can place a food order through registered restaurants.


Customer can request a local bike or car ride.


Partner can complete a bike/car trip.


Admin can manage customers, partners, restaurants and requests.


Admin can monitor payments, commissions and partner earnings.


Core request statuses are stored in history and visible to authorized users.


19. Out of Scope for Phase 1


Bus ticket booking.


Train ticket booking.


Mobile recharge.


Utility bill payment.


Flight/hotel booking.


Large catalogue-based grocery marketplace.


Inter-city transportation marketplace.


Advanced subscription/membership plans unless separately approved.
